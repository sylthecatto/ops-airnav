## Step 8: New pull error after fixing the address

```
Failed to pull image "192.168.10.23:5000/new-app:1.0":
Head "https://192.168.10.23:5000/v2/new-app/manifests/1.0": http: server gave HTTP response to HTTPS client
```
Address is correct now. containerd is using HTTPS against an HTTP-only registry.

```bash
cat /var/lib/rancher/k3s/agent/etc/containerd/certs.d/192.168.10.23:5000/hosts.toml
```
```toml
server = "https://192.168.10.23:5000/v2"
[host."http://192.168.10.23:5000/v2"]
  capabilities = ["pull", "resolve"]
```
This file is generated by k3s from `registries.yaml`. The `server` fallback defaults to https regardless of the mirror endpoint's scheme.

**Problem 8:** containerd defaults to HTTPS. Fix, on all three nodes:
```bash
cat > /etc/rancher/k3s/registries.yaml <<'EOF'
mirrors:
  "192.168.10.23:5000":
    endpoint:
      - "http://192.168.10.23:5000"
configs:
  "192.168.10.23:5000":
    tls:
      insecure_skip_verify: true
EOF
systemctl restart k3s          # node20 only
systemctl restart k3s-agent    # node21, node22
```
Note: editing the generated file directly does not work — k3s overwrites it from `registries.yaml` on every restart. Must edit the source file.

## Ingress setup

Traefik (ships with k3s) already holds IPs before any Ingress object exists:
```
service/traefik   LoadBalancer   192.168.8.121,192.168.8.233,192.168.8.245   80:30710/TCP
```
An Ingress is a routing rule, not an IP source — it tells Traefik which Service to send a request to based on the Host header. Multiple apps share the same IPs, split by hostname.

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: new-app-ingress
  namespace: startup
spec:
  ingressClassName: traefik
  rules:
  - host: new-app-staging.192.168.8.121.nip.io
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: new-app-svc
            port:
              number: 80
```

First attempt used `.local` hostnames — required a manual hosts-file entry on every machine. Switched to `nip.io`: public DNS, `anything.<ip>.nip.io` resolves to `<ip>` automatically, no client-side config needed.

Verified routing before trusting DNS:
```bash

```
